# 字符串加密分析文档

## 概述

此 APK 使用了深度字符串加密混淆。经分析，存在两类加密字符串：

1. **阿拉伯字母标识符** (~1100 个) - 用于控制流扁平化的状态标识
2. **类 base64/hex 字符串** (~100 个) - 加密的类名、方法名、资源名

## 关键发现

### 1. 解密函数分析

jadx 反编译显示多个解密函数：
- `C0113.m410(String)` - hex 字符串解密（原 `m173`）
- `C0117.m1137(short[], int, int, int)` - short 数组 XOR 解密（原 `m905`）

**重要**：jadx 反编译的 Java 代码包含逻辑错误（无限循环），与真实 APK 可正常运行矛盾。说明：
- 真实字节码逻辑与 jadx 反编译结果不一致
- 或这些代码路径在运行时不会执行
- 解密在 Smali 层通过不同机制完成

### 2. 加密字符串分类

#### A. 阿拉伯字母状态码（~1100 个）

示例：`۟۟`, `۟۟۠`, `۟۟ۡ`, `ۣ۠ۤ`, `ۦۣۤ`

用途：控制流扁平化中的 switch-case 分支标识

### 3. 短数组 XOR 加密

在 `C0001a.java` 中可见：
```java
C0117.m1137(m283(), 0, C0113.f191 ^ 416, 1723)
C0117.m1137(m272(), 269, C0113.f191 ^ 433, 2212)
```

这些调用从 short 数组解密字符串，参数含义：
- 参数1: short 数组
- 参数2: 起始偏移
- 参数3: XOR 密钥（基于常量字段计算）
- 参数4: 字符串长度

## 解密限制说明

**为什么无法完全静态解密：**

1. jadx 反编译的控制流逻辑与真实字节码不一致
2. 解密函数包含反调试/反分析陷阱（无限循环）
3. 密钥派生依赖运行时状态
4. 部分字符串可能在运行时动态生成

**保证 APK 正常运行的方法：**

保留原始 Smali 字节码不变。字符串解密在运行时由 Dalvik/ART 虚拟机正确执行。

## 使用建议

如需进一步分析，建议：
1. 在 Android 模拟器中使用 Frida/ Xposed 动态 hook 解密函数
2. 捕获运行时解密后的明文字符串
3. 或使用 ART 虚拟机级别的字符串拦截
